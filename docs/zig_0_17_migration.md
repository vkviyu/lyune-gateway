# Zig 0.17 迁移评估（已撤回）

> 决定日期：2026-10-08。当前审计基线固定为 **Zig 0.16.0**，本文不是当前构建指南。

## 决定与原因

曾在本机尝试迁移到 Zig 0.17，并进行代码回归；但该尝试使用的 libxev 适配来自当时尚未合并的上游 PR #250。项目所有者决定先恢复原有 0.16 工具链与依赖，提交已有审计修复，再继续逐行审计，不把依赖迁移与架构审计混在一起。

## 当前仓库状态

- 撤回 0.17 的语法、标准库与构建 API 改动，保留原有 `@cImport` 绑定方式；
- libxev 恢复固定提交 `9ce8e8e6ff89e583258a7f8e7adeeeaeae8611bf`，不采用上述 PR 适配；移除本次新增的 `translate-c` 依赖；
- `.zigversion` 修正为 `0.16.0`，与根包、BoringSSL 构建包装和文档一致；不恢复此前过时的 `0.15.2` 标记；
- 保留迁移前已获准的 realm 全编号配额修复、`gateway_ctx` 清理及相关回归；
- 不创建 tag 或 release，也不启动远程 Linux 验证。

当前命令与回归结果见 [README](../README.md#构建与测试) 和 [实现状态](status.md#2-已验证范围)。0.17 尝试中的测试与 Linux 交叉编译结果不作为当前 0.16 基线的运行验收证据。

## 后续门禁

先完成 [源码逐行审计](code_audit.md)，处理确认的缺陷并做 Mac 回归，再由项目所有者确认进入远程 Linux 测试。工具链升级是单独决策，未来重新评估依赖支持情况后再做，不自动恢复本次迁移。
