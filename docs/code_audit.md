# 源码逐行审计

> 基线日期：2026-09-01
>
> 状态：进行中。功能演进、远程 Linux 验证和版本发布暂停。

本文记录 Lyune Gateway 当前阶段的源码审计范围、顺序、证据和结论。目标不是立即增加功能或进行大规模重构，而是让项目所有者能够逐行理解现有实现，确认架构边界、状态所有权和失败语义，再决定下一轮演进方向。

## 1. 当前冻结规则

- 不新增协议能力、传输 binding、业务功能或部署模式；
- 不因为“看起来更优雅”而顺手重构；先记录问题、影响和证据；
- 暂不开始远程 Linux 阶段，也不把 Mac 结果外推为跨平台或生产结论；
- 不创建 tag、release、镜像或兼容性承诺；
- 审计中发现确定的正确性或安全缺陷时先记录。只有缺陷阻断审计、破坏当前验证基线，或得到明确决定时才修改代码；
- 文档、注释、配置与源码事实不一致时可以直接修正，但不得借文档整理改变协议语义。

## 2. 审计目标

逐个模块回答以下问题：

1. 模块只负责什么，又明确不负责什么；
2. 每份状态由谁创建、拥有、修改和释放；
3. 一条请求、响应、推送、取消和关闭怎样穿过调用链；
4. Raw QUIC 与 WSS 在哪里分流、在哪里汇合，是否共享完全相同的业务语义；
5. 容量、超时、背压、错误和重试分别在哪一层生效；
6. realm、连接身份、路由和授权在何处建立信任边界；
7. 多 Worker、后端连接池和集群路径的并发假设是否能由代码证明；
8. 文档、配置、测试和真实运行证据是否与实现一致。

| 顺序 | 范围 | 重点 | 状态 |
| --- | --- | --- | --- |

| 3 | `src/session/` | `TransportSession` 契约、handle 生命周期、vtable 边界 | 待审计 |
| 4 | `src/quic/`、`src/wss/` | 两种 binding 的适配、逻辑流映射、队列和取消语义 | 待审计 |
| 5 | `src/worker/connection.zig`、`ingress.zig`、`auth.zig` | 连接上下文、realm、认证和客户端输入 | 待审计 |
| 6 | `src/worker/inflight.zig`、`egress.zig`、`lifecycle.zig` | Exchange、响应回程、push、presence 和回收 | 待审计 |
| 7 | `src/backend/` | `ScopedRoute`、DirectTransport、连接池、接收槽位和故障隔离 | 待审计 |

## 4. 发现项分类

审计发现统一按以下类别记录，避免把猜测直接升级成改造任务：

- `DOC`：文档、注释或配置示例与代码不一致；
- `READABILITY`：命名、模块边界或控制流妨碍理解，但尚未证明影响正确性；
- `ARCH-DEBT`：职责或依赖方向存在结构性问题；
- `CORRECTNESS`：能给出输入、执行路径和错误结果的确定缺陷；
- `SECURITY`：信任边界、身份、证书、输入校验或资源耗尽风险；
- `PERF-HYPOTHESIS`：性能假设，必须先用基准或 profile 量化；
- `DECISION`：需要项目所有者在多种语义之间作选择。

`TransportSession` 的 vtable 调用成本目前属于 `PERF-HYPOTHESIS`：它位于事件和 I/O 操作边界，尚无数据证明是热点。在保持 Raw QUIC/WSS 统一业务路径的收益面前，不应仅凭存在间接调用就改回分叉实现；应在性能阶段用调用频率、CPU profile 和端到端延迟数据决定是否需要静态特化或批处理。

## 5. 单项记录模板

```text
编号：AUDIT-XXX
范围：文件、类型或调用链
类别：DOC / READABILITY / ARCH-DEBT / CORRECTNESS / SECURITY / PERF-HYPOTHESIS / DECISION
事实：代码现在实际做什么
不变量：必须始终成立的条件
证据：行号、测试、日志或最小复现
影响：错误结果、维护成本或资源风险
结论：接受 / 补文档 / 待测量 / 待决定 / 允许修复
验证：修改后需要重跑的最小集合
```

## 6. 当前已确认事项

- Raw QUIC 与 WSS 都通过 `TransportSession` 汇入相同 Worker 业务路径；WSS 不是另一套 IM 协议；
- 已有真实用户验证表明 WSS 会话能读取 Raw 用户持久化的群消息，并且双方同时在线时 Raw→WSS、WSS→Raw 两个方向的新消息都能实时到达；这证明共享认证、路由、SQLite 历史和双向在线推送链路；
- 双向实时互通的人工证据已经关闭，但不能替代错误密码、注册、建群/入群等完整 UI 操作清单；
- 默认本地配置的 Gateway 前端端口与 Reactor 后端端口必须分离；文档和配置统一使用 UDP 8443 / TCP 8444 接入 Gateway、UDP 9443 接入 Reactor；
- 远程 Linux 验证仍然必要，但是否以及何时开始，要在本轮源码审计结束后重新决定。

## 7. 审计完成条件

- 上述模块均有明确的状态所有权、调用链和失败语义结论；
- 所有发现项已分类并有证据，没有把性能猜测当成事实；
- README、`status.md`、协议/架构文档与当前实现能够互相印证；
- 对“接受现状、局部重构、协议调整、继续 Mac 验证或进入 Linux”形成一份按风险排序的决策清单；
- 项目所有者明确确认下一阶段后，才更新 `roadmap.md` 并解除相应冻结项。
